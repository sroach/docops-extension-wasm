## SVG Rendering Requirements

- All generated SVGs must support both light and dark mode.
- Use CSS variables and `prefers-color-scheme` media queries so the SVG automatically switches based on system settings — do not hardcode colors that would break dark mode.
- When designing or updating the visual style of an SVG, apply the **`premium` design skill**:
    - Skill definition: `.junie/skills/premium/SKILL.md`
    - Design tokens (colors, typography, spacing): `.junie/skills/premium/DESIGN.md`
    - Follow the token values and rules defined in these files (e.g. primary `#3B82F6`, Inter/JetBrains Mono typography, 4/8/12/16/24/32 spacing scale) rather than inventing new values.
    - Prioritize accessibility (WCAG 2.2 AA, visible focus states, sufficient contrast) over novel styling choices, per the skill's rules.
    - The design should follow Apple inspiration.

## SVG Accessibility & ARIA Requirements (WCAG 2.2 AA)

Every visual generated by DocOps must implement semantic accessibility features:

1. **Root SVG Semantics & Metadata**:
   - The root `<svg>` element must include `role="graphics-document document"` (or `role="status"` for badges / `role="group"` for interactive button collections).
   - Link title and description metadata with `aria-labelledby="{id}_title {id}_desc"`.
   - Provide dynamic, informative `<title id="{id}_title">...</title>` and `<desc id="{id}_desc">...</desc>` tags summarizing the visual and key statistics.

2. **Component & Data Item ARIA Mappings**:
   - **Data points, bars, slices, lines**: `role="graphics-symbol"`, `aria-roledescription="bar|slice|data point|line|gauge"`, `tabindex="0"`, and an informative `aria-label` (e.g., `aria-label="Q1: $125,000 revenue"` or `aria-label="Storage: 45GB (65%)"`).
   - **Series & Groups**: `role="group" aria-label="{series_name} series"`.
   - **Legends**: `role="list" aria-label="Legend"` with each item as `role="listitem" aria-label="{item_name}"`.
   - **Tabular Data (Gherkin step tables, Examples)**: `role="table"` container, `role="row"` for table rows, `role="columnheader"` for header cells, and `role="cell"` for data cells.
   - **Status Badges & Chips**: `role="status" aria-label="Status: {status_name}"`.
   - **Landmark Cards & Sections (Gherkin Scenarios, ADR Sections, Scorecard Cards)**: `role="region" aria-label="{Section / Scenario Title}"`.
   - **Interactive Links & Buttons**: `role="link"` or `role="button"`, `tabindex="0"`, with high-contrast `:focus-visible` outlines.

3. **Separation of Decorative and Informational Graphics**:
   - Apply `aria-hidden="true"` to ambient glows, decorative gradients, background cards, drop-shadow targets, sonar/grid patterns, connecting lines, pulse rings, and purely decorative icons that duplicate adjacent text.
   - Ensure all meaningful text, data labels, and values are either exposed via readable `<text>` elements or clear `aria-label` attributes.
